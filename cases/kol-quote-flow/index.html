CASE · 自动化工作流

海外 KOL 报价
自动化工作流

KOL 来谈合作的报价邮件，自动整理成结构化数据，人工确认后同步进飞书多维表格。把运营从手动抄表里解放出来。

AI自动化工作流飞书Gmail

▶ 打开无代码配置后台（原型） 客户不用懂代码，全程页面操作

它解决什么

做海外 KOL 营销，每天一堆达人发来报价邮件，运营要手动一封封读、抄进飞书表，慢又容易抄错。这条流水线把读取和整理交给 AI，运营只需做最后一步把关。

整体流程

Gmail（报价邮件） │ 打标签 KOL报价，定时轮询 ▼ AI 结构化抽取（模型可随意切换） │ KOL / 平台 / 粉丝量 / 报价 / 币种 / 合作形式 … ▼ 本地暂存「待确认」 │ 审核台：左看原邮件，右改字段 ▼ 人工点确认 → 写入飞书多维表格

关键设计：AI 抽完不直接入库，先进「待确认」，人核对/修改后点确认才写飞书——既省人力，又不让 AI 的误读直接污染数据。

四个模块

① 抓邮件

Gmail API 按标签轮询，只读权限，单业务邮箱场景最稳。

② AI 抽取

结构化输出约束成固定字段 JSON；模型可一行切换 Claude / OpenAI / 国产各家。

③ 人工确认

网页审核台，原邮件与抽取字段并排，可编辑后一键通过/驳回。

④ 写飞书

飞书开放平台 API，确认后 append 一条记录进多维表格。

模型与成本

抽取是轻任务，可按量级在最便宜与最准之间选：

模型价格（输入/输出 每百万 token）适用
Haiku 4.5$1 / $5量大、省钱
Sonnet 4.6$3 / $15均衡
Opus 4.8（默认）$5 / $25最准

一封报价信约 2K 输入 + 0.3K 输出：Haiku ≈ $0.0035/封，Opus ≈ $0.018/封。非实时还能接 Batch API 再打 5 折。

交付形态

一套可在客户自有服务器上 npm start 跑起来的 Node.js 服务（含审核台前端），密钥走 .env，不进代码、不进前端。技术方案与部署步骤见仓库 cases/kol-quote-flow/README.md。

这是一套后端服务，需自有服务器与三套密钥（大模型 / Gmail / 飞书）才能运行，故案例库这里展示方案与界面，源码在仓库对应目录。
